# Encrypted application snapshot contract

`/sync/data` transfers one encrypted application snapshot per account. The desktop owns the application data structure and encryption key; the service authenticates the account, checks the outer request, and stores the ciphertext unchanged. Changes to the provider/model tree require no service database migration or new API fields.

## HTTP envelope

`PUT /sync/data` accepts:

```json
{
  "ciphertext": "opaque-client-encrypted-envelope",
  "updatedAt": 101,
  "expectedUpdatedAt": 100
}
```

| Field | Meaning |
| --- | --- |
| `ciphertext` | Nonempty string generated by the desktop. The default maximum size is 16 MiB. It is not a plaintext config object. |
| `updatedAt` | Nonnegative safe integer requested by the client. The stored version is the greater of this value and the previous version plus one. |
| `expectedUpdatedAt` | Optional write precondition. `null` requires no existing snapshot; an integer requires that exact existing version. Omission keeps legacy unconditional uploads compatible. |

A successful upload returns `204`. `GET /sync/data` returns exactly `{ "ciphertext", "updatedAt" }`, or `404` if no application snapshot exists. A failed precondition returns `409` and `X-SSHStar-Current-Version` without replacing the stored ciphertext. After success, clients obtain the accepted version from `GET`; after a conflict, they download, merge, and retry with the new precondition.

The current desktop encodes `ciphertext` as a string containing an AES-256-GCM JSON envelope with `version`, `algorithm`, `nonce`, and `ciphertext`. Its `version: 1` describes the encryption envelope, not a provider schema version. The server does not parse this inner envelope or possess the cloud encryption key.

## Application data inside encryption

The following is an illustrative **decrypted** `aiConfig` fragment. It is encrypted together with servers, groups, conversations, collapsed groups, and `syncMeta` before upload; it must not be sent as a plaintext HTTP body.

```json
{
  "aiConfig": {
    "selectedProviderId": "provider-primary",
    "providers": [
      {
        "id": "provider-primary",
        "name": "Primary provider",
        "apiMode": "responses",
        "endpoint": "https://api.example.com/v1",
        "apiKey": "example-key-inside-client-encryption",
        "selectedModelId": "reasoning-model",
        "models": [
          {
            "id": "reasoning-model",
            "reasoningEfforts": ["auto", "high", "xhigh"],
            "defaultReasoningEffort": "high",
            "reasoningEffort": "xhigh"
          },
          {
            "id": "fast-model",
            "reasoningEfforts": ["auto", "none"],
            "defaultReasoningEffort": "auto",
            "reasoningEffort": "auto"
          }
        ]
      }
    ],
    "apiMode": "responses",
    "endpoint": "https://api.example.com/v1",
    "model": "reasoning-model",
    "reasoningEffort": "xhigh"
  }
}
```

| Encrypted field | Client behavior |
| --- | --- |
| `aiConfig.providers` | Ordered list of independently configured providers. Each provider has its own stable `id`, display name, API mode, endpoint, credential, models, and remembered model selection. |
| `selectedProviderId` | Provider currently used by the assistant. |
| `providers[].selectedModelId` | Last selected model for that provider. Model IDs may be identical across different providers. |
| `models[].reasoningEfforts` | The available reasoning choices configured for this model. Supported values are `auto`, `none`, `minimal`, `low`, `medium`, `high`, and `xhigh`. |
| `models[].defaultReasoningEffort` | Default reasoning choice for that model. |
| `models[].reasoningEffort` | Remembered current choice for that model. |
| Top-level `apiMode`, `endpoint`, `model`, `reasoningEffort` | Compatibility fields derived from the current provider and model. |
| Other `aiConfig` fields | Agent, tools, import/export, cloud-sync settings, and future extensions remain part of the encrypted config. |
| `syncMeta.aiConfigRevision` | Revision used by the desktop to merge the entire AI config category across devices. The service does not merge individual providers or models. |

Provider/model order and every unknown extension field remain intact because the service returns the exact ciphertext it received. Adding, deleting, renaming, or changing providers and models is synchronized by uploading the new complete snapshot. There are no plaintext provider endpoints or server-side model discovery calls.

The settings editor's selected tree node and expanded/collapsed nodes are local navigation state and are not synchronized. These are separate from the assistant's saved `selectedProviderId`, per-provider `selectedModelId`, and per-model reasoning choices.

## Credentials and key backups

The desktop loads provider API keys from the system credential store and inserts them into the snapshot **before encryption**. When downloading, it restores each key under that provider's ID and strips keys from the local application database. The service stores no plaintext API keys and does not receive the local credential-store account names or encryption keys.

`/sync/keys` remains a separate opaque, passphrase-encrypted backup of SSH `*.key` files. Provider API keys belong to the encrypted application snapshot in `/sync/data`, not this SSH key-file backup. Clearing an application snapshot and clearing a key-file backup remain separate operations.

## Compatibility and rollout

- Existing single-provider snapshots with only top-level `endpoint`, `apiKey`, `apiMode`, `model`, and `reasoningEffort` remain valid encrypted content. The current desktop migrates them into a provider with ID `default` after decryption.
- Existing clients can continue using the same HTTP envelope without `expectedUpdatedAt`. Current clients use the precondition to avoid replacing a newer snapshot with one based on an older cloud version.
- The server cannot migrate encrypted content or make a legacy desktop understand provider lists. An unconditional upload from an older desktop can still replace a snapshot; update desktops before editing the same AI config across versions.
- Preserve the service database and signing secret during upgrades. The same stored ciphertext and login sessions are available after restart. The client cloud encryption key is also required to decrypt data on another device.

`server/test/provider-sync.test.mjs` verifies a real AES-GCM round trip from a legacy snapshot to multiple providers, all model/selection/reasoning fields, unknown extensions, encrypted credential storage, stale-write rejection, and persistence after a service restart.
